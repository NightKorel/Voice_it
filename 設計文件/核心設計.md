# 聲控守家遊戲・核心設計（Voice_it）

> 這份檔案**只放納可拍板的東西**。腦補、提案、還沒定的，放最下面的「待釐清」或 `點子庫.txt`。
> 遊戲正式名稱：**尚未命名**。

---

## 一句話說明

**一個用「聲音」玩的守家遊戲。** 你指揮一支三人小隊，用喊的把隊員派去左右兩邊擋住成波湧來的敵人；關鍵時刻喊出隊員的專屬大招；敵人放大招時，要在三次內把螢幕跳出的繞口令唸對來反彈。在家的血扣光前撐過去。

---

## 平台與技術路線（已定案）

- **純前端**（HTML + CSS + 原生 JavaScript），放 **GitHub Pages**，免費。
- 玩家端需求：**Chrome / Edge、要連網、要給麥克風權限**。
- **辨識一律走「模糊比對／容錯」，不要求一字不差**（因為同一句每次辨識都會飄，這是語音辨識的天性，消不掉，只能靠容錯撐）。換辨識工具也消不掉這個飄，只會飄多飄少的差別，所以容錯永遠要做。
- **辨識工具：先用 Web Speech API**（零安裝、即時、最省事，代價是限 Chrome/Edge、玩的過程要一直連網）。
  - 本地模型（Whisper via Transformers.js／Vosk）是**之後才考慮的升級**，真正的好處是「**不挑瀏覽器＋玩到一半不怕斷線**」（不是「離線」——遊戲在 GitHub Pages 上，開場本來就要連網）。代價是要下載模型、較吃效能、程式複雜很多。等有人真的反映 Safari 玩不了或斷線很煩再換。

## 小隊（已定案）

- **三個角色**，職業固定為：**劍士、弓箭手、法師**。
- **玩家幫每個角色自己命名**（用打字設定）。
- **三人共用一條血**（＝塔樓的血，見下方「塔樓與敵人數值」）。
- **沒有回血機制**——血只會扣不會補（升級提高血上限不算回血）。所以遊戲性格是「在血扣光前把敵人清掉」，偏短關卡、爽度導向。

### 為什麼是這三個職業
它們的差別是「怎麼打、打哪裡」，剛好給「派誰去哪邊」有講究：
- **劍士**：近戰，敵人貼近時最猛。
- **弓箭手**：遠程，敵人還遠就能點。
- **法師**：範圍，敵人擠成一坨時清一片。

## 戰場與操作（已定案）

- **守家遊戲**：家在中間，敵人**分別從左、右兩邊**成波湧來（只有兩邊，刻意不做四面八方，才不會讓玩家嘴巴忙不過來）。
- **點名派位**：喊「〔角色名字〕，左！／右！」→ 把那個隊員調去該邊，**他就自動攻擊那邊的敵人**。
  - 玩家平常只在「需要重新分配」時開口，不用每隻怪都喊——降低嘴巴負擔，手感像「隊長調兵」而不是手動操作每個人。
- **核心判斷**：三個人分兩邊，永遠有一邊比較空虛，看哪邊敵人多／快破就趕快調人過去補。

## 塔樓與敵人數值（已定案）

- **塔樓（＝家／基地，三人共用的血）血量＝ 100**，可用錢升級（提高血上限）。
- **敵人只有兩個數值**（刻意極簡）：
  - **血量**：最小的怪＝ 1，比較大的怪才會更高。
  - **攻擊力**：敵人走到塔下後，每次攻擊會讓塔掉多少血。
- 敵人打死會**掉錢**，錢用來買強化（見下）。

### 敵人圖鑑（陸續增加）
- **史萊姆 🔵**：一開始的基本小怪。血量 1（最小的怪），藍色圓圓的。

## 強化菜單（已定案）

- 升級菜單有**四項**：**劍士、法師、弓手、塔樓**。
- 用敵人掉的錢購買，讓這一局越打越強（roguelite 的核心爽感來源）。
- 各項「具體能買什麼強化、強化什麼、多少錢」尚未定案（見「待釐清」）。強化風格可數值型（無腦變大）也可玩法型（改變機制），兩種都能有。

## 大招（已定案）

- **每個角色有一個專屬大招**。
- **喊「〔角色名字〕，大招！」點名發動**（所以「名字」不只是氣氛，是用來指定「放誰的大招」）。

---

## 大招反彈・繞口令（已定案）

- **只有 Boss（每關第五波）會放大招**——一般小怪不會逼玩家唸繞口令。所以繞口令反彈是**每關 Boss 戰的招牌高潮**。
- Boss 放大招時畫面警告，玩家要在**三次以內**把螢幕跳出的**繞口令**唸對 → **成功就反彈**（把大招彈回去）；三次都失敗 → **塔的血吃一記重傷**。
- 繞口令是**隨機一句**跳出來。
- **繞口令用「真的中文句子」**（不是自創詞），所以語音辨識本來就聽得懂、不用玩家事先錄音，遊戲內建一批即可。
- **難點來自玩家自己舌頭打結，不是機器聽不懂**——玩家只會笑自己、不會怪遊戲。
- 「三次機會」同時也是**內建容錯**（偶爾聽錯一次還有救）＋製造「只剩最後一次」的心跳感。

### 容錯規則（已定案）
- **辨識結果跟正確繞口令「差三個字以內」就算對。**
- （之後可考慮：容錯字數**隨句子長度調整**——長句給三個字、短句給一兩個字，避免短繞口令太好過。歸在「待釐清」。）

## 指令的辨識做法（已定案）

- **玩家自訂的指令（名字＋動作）**走「**錄一次再比對**」：玩家設定時錄，之後喊出來比對「像不像同一句」。系統不需要「聽懂」內容，所以名字可以是自創詞、中二名，照樣認得。
  - **建議設定時多錄幾次**，把「每次辨識會飄」的多種結果都存起來當「這句的許多長相」，喊出來像其中任一種就算對。
  - **名字要進辨識比對**（開場各錄一次，一次性設定；動作指令可共用）。
- **繞口令**走「內建真句＋辨識比對」（見上）。
- **指令彼此發音要拉開差異**（名字別取太像、動作別太像），否則模糊比對會分不清、容易點錯人。
- 若哪天模糊比對仍不夠穩，備案是「**直接比對聲音波形**」（不靠辨識、可離線），但複雜度高很多，非必要不先做。

## 遊戲類型與局的結構（已定案）

- **定位：輕量 roguelite（輕 rogue）小遊戲。** 不追求數值平衡，**以「玩家開心」為最高原則**——夠爽、夠好玩就對了，不用斤斤計較平衡。
- **一局（一次 run）＝三關，每關五波怪**（共 15 波）。
- **敵人會掉錢。**
- **掉的錢可以買強化**（升級菜單四項，見下），越打越強，是這局變強的來源。
- **神秘商人**：每關的**偶數波（第 2、4 波）**會出現，賣**酷東西**（比一般升級菜單特別／稀有的道具）。
  - **核心抉擇**：錢**早早花在一般升級**，還是**忍住存起來留給商人**買酷東西？這個「花現在 vs 等以後」的取捨就是 roguelite 的樂趣所在。
- **每關第五波固定是 Boss。** 所以每關節奏＝正常波 → 商人 → 正常波 → 商人 → Boss 壓軸。

## 完整遊戲循環（目前樣貌）

> 三關、每關五波：敵人從左右兩邊成波來 → 喊「〔名字〕，左／右」把三人分配去擋（自動攻擊）→ 吃緊時喊「〔名字〕，大招」放專屬絕招 → 遇到會放大招的敵人，限三次內唸對繞口令反彈 → 打死敵人掉錢 → 用錢買強化，偶數波還有神秘商人賣酷東西（花現在 vs 存起來的抉擇）→ 在塔的血扣光前撐過三關。

## 🟡 待釐清（還沒拍板，之後再想）

- **波次細節**：三關×五波、偶數波商人、第五波 Boss 已定案；但每波／每關越來越難的幅度、一般升級菜單能在什麼時機買（隨時？波間？）還沒定。
- **Boss**：三關各自的 Boss 是誰、長怎樣、大招各是什麼，還沒定。（已定：Boss 才有繞口令大招。）
- **強化菜單內容**：四項（劍士／法師／弓手／塔樓）各能買什麼強化、強化什麼、多少錢，都還沒定。
- **音量玩法**：早期定「音量是主要玩法」，但守家玩法成形後，音量具體要控制什麼還沒定（要不要保留？當氣勢／強度？）。
- **難度分級**：繞口令難度要不要跟敵人強弱走；容錯字數要不要隨句長調整。
- **大招冷卻**：大招要不要有冷卻／充能（避免一直放、跳過派位樂趣）。傾向要，但納可還沒拍板。
- **大招具體效果**：三個職業的大招各長怎樣（初步方向見 `點子庫.txt`，尚未定案）。
- **遊戲名稱**：還沒取。
